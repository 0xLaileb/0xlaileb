<details>
<summary>How to submit</summary>

1. Find the 16-character flag. It looks like `0xL{...}`.
2. Compute `sha256("<flag>:<your GitHub login in lowercase>")`. The [debugger](https://0xlaileb.github.io/0xlaileb/) has a Crackme tab that does it in your browser.
3. Open an issue titled [`crackme <64 hex digits>`](https://github.com/0xLaileb/0xlaileb/issues/new?title=crackme+PASTE_YOUR_PROOF_HERE).

The proof only works for your own login, so nobody can copy it, and the flag itself never appears in public. Please keep it that way.

</details>

<details>
<summary>How this page works</summary>

```mermaid
flowchart LR
    V([Visitor]) -- "issue: poke / crackme" --> I[GitHub Issues]
    I -- "issues: opened" --> P[play.py<br>validate, label, close]
    C([Daily schedule]) --> R
    P -- accepted --> R[profile_svg.py<br>render SVG cards + data.json]
    A[(GitHub GraphQL<br>and REST API)] --> R
    R --> O[(output branch)]
    O --> M[This README]
    O --> S[GitHub Pages debugger]
```

No state is stored in the repository: the shared memory and the hall of fame are rebuilt on every run from the closed issues that the workflow labelled. Everything is generated by one dependency-free Python script in [`tools/`](tools).
